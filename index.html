LLM Code Deployer
Source Console

A brief goes in, a live website comes out.

Send a one-paragraph description of a small web app. This FastAPI service asks an LLM to write it, pushes the files to a new GitHub repository, turns on GitHub Pages and waits until the page is live. It was built for the IITM Tools in Data Science course, where an evaluator sends the briefs.

What happens to a request

Each step below maps to code in main.py. The request returns as soon as it is accepted; the rest runs in the background.

  1. Check the request

    Pydantic validates the JSON body and the shared secret is compared in constant time. A wrong secret gets a 403 before any work starts.

  2. Read the attachments

    Files sent as data URIs or links are decoded and passed to the model as context.

  3. Ask the LLM for the files

    call_llm requests one JSON object of filename to content. It tries an OpenAI-compatible endpoint (AI Pipe) first, then Gemini models, two attempts each.

  4. Create or revise the repository

    Round 1 creates a new public repository. Round 2 reads the code already there and asks the model for a revision.

  5. Commit the result

    The generated files are committed with a README and an MIT licence.

  6. Publish and verify

    GitHub Pages is turned on, then the Pages URL is polled until it answers or the timeout (180 seconds by default) runs out.

  7. Report back

    The repository URL, commit SHA and Pages URL are posted to the callback URL, retrying up to four times with 1, 2, 4 and 8 second waits.

Call it

The service is protected by a secret, so these examples will not run without it. They show the exact shape of the API.

Request

curl -X POST https://24f2007692-llm-code-deployer.hf.space/api/build \
  -H "Content-Type: application/json" \
  -d '{
    "email": "you@example.com",
    "secret": "<server secret>",
    "task": "unit-converter",
    "round": 1,
    "nonce": "any-unique-string",
    "brief": "A unit converter for length and weight with a dark mode toggle.",
    "evaluation_url": "https://your-server.example/callback",
    "checks": ["document.querySelector(\"#convert\") !== null"]
  }'

Immediate response

{
  "status": "accepted",
  "message": "The build and deploy process has been started in the background."
}

Posted to the callback URL when the site is live

{
  "email": "you@example.com",
  "task": "unit-converter",
  "round": 1,
  "nonce": "any-unique-string",
  "repo_url": "https://github.com/<owner>/unit-converter",
  "commit_sha": "<sha>",
  "pages_url": "https://<owner>.github.io/unit-converter/"
}

GET /api/status reports whether the LLM providers and GitHub are configured, without revealing any keys.

Limits

  • Builds run as in-process background tasks. There is no job queue, so a restart loses builds in progress.
  • One shared secret protects the build endpoint. There are no user accounts or per-user rate limits.
  • The checks are passed to the model as requirements. The service does not run them against the generated site.
  • There are no automated tests in the repository yet.
  • The generated code is whatever the model writes. It is published without human review.
